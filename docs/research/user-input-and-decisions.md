# 用户需求与决定记录

记录日期：2026-11-07。来源是本项目用户输入与后续确认，不作为宿主已经具备相应能力的技术证据。

## 首要问题

编程Agent的工具调用内容迅速占满上下文。用户特别看重Magic Context能逐步卸载早期内容并按需恢复原文，认为这是其相对普通记忆插件的关键差异。项目不是单纯增加知识记忆或摘要。

## 用户最初要求保留的能力

### 上下文管理

- 后台Historian把旧原始历史整理为按时间排列的分层分区，带重要性分数；可独立使用便宜或本地模型，不占用主Agent的高价编码模型。
- 确定性衰减渲染：按年龄、重要性及模型上下文预算选择保真度，不依赖每轮LLM重新总结。
- 代理驱动缩减：ctx_reduce标记过时工具输出或长消息，操作排队，在缓存安全的时机应用。
- 关闭Agent参与时，按年龄自动卸载；最旧文本的caveman压缩为可选能力。
- 缓存稳定布局：后台工作不随意使请求前缀失效。产品目标不应被误读为永久命中保证。

### 捕获、存储和巩固

- 希望研究按项目存储，以及文本存储是否更合适；没有要求必须先重写全部持久化。
- 已澄清：上游采用全局SQLite不等于项目数据逻辑上混在一起。项目隔离、存储位置、可编辑格式分别决策。
- 巩固若移植复杂，可降低优先级并考虑V2；不是永久删除Dreamer。

### 回忆

- 每轮自动、缓存稳定地注入活动项目记忆和压缩历史，跨新会话继承。
- ctx_search跨项目记忆、原始对话及可选Git commit索引检索；语义嵌入并有全文回退。
- ctx_expand按tag、消息或历史范围找回原始内容，而不是从摘要生成替代品。
- ctx_note保存延迟意图，在提交、Historian、todos完成等自然边界重新呈现；开放条件Smart notes依赖Dreamer，需分开排期。
- 希望可跨harness使用；未来可扩展与立即直接共享现有OpenCode/Pi数据库是不同兼容要求，尚未选定。
- 自动搜索提示默认开启：后台搜索只追加紧凑线索，不注入完整结果；目标配置语义包括 `memory.auto_search.enabled: false` 可关闭。
- Git commit索引选择开启；目标配置语义包括 `memory.git_commit_indexing.enabled: true`。具体DSH配置映射尚未实现。

### UI

用户认为DSH支持插件UI，希望逐步把上游桌面管理功能做到插件内，不以另造桌面应用为前提。UI不属于当前阶段0验证。

## 已确认决定

1. 项目名为dsh-magic-context。
2. 固定MC版本，复用选定源码、提示词与测试，独立维护DSH adapter；不是只参考功能重写。
3. 已批准四问题只读源码研究并完成；基线是MC v0.49.40 / 33fb6ac9、DSH fcc0ad46，本机CLI观察为0.2.2-rc.1。
4. 已确认先编写阶段0计划：隔离Windows/已安装DSH、文本/JSON工具内容、离线闭环。尚未选执行方式或授权实现。
5. 用户另行授权把研究全部落盘，初始化Git、设置忽略规则、创建GitHub仓库并推送。该授权不包含实施阶段0代码。
6. 用户明确项目计划开源并委托选择协议；采用MIT，与两端上游顶层许可证一致，具体依赖仍逐一核对。
7. 较重且非研究规划的子代理任务优先deepseek-v4.1-flash，尤其开发和评审；规则已写入AGENTS.md。

## 仍未决定

- 完整V1功能边界与Historian/记忆/UI的具体版本切分。
- 最终数据所有权、数据库位置、文本编辑与Git同步需求的优先级。
- 项目身份在worktree、不同克隆、非Git目录之间的共享方式。
- 跨harness直接互读的兼容层级。
- 正式支持的DSH版本与模型/提供商组合。
- 插件禁用后只需日志/导出可读，还是必须自动恢复模型可见原文。
- 阶段0计划的审核、执行方式和实现启动授权。

公开发布方向已明确，不再把“自用还是开源”记为未知；但开源不等于这些支持范围已经确定。具体研究、设计提议和可执行步骤分别见[总索引](README.md)，不把提议误记为用户批准。
